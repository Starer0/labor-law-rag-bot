## 一、整体目标

把劳动法规 PDF 变成可问答的知识库，链路：

```
PDF 文档 → 拆成小块 → 向量化(bge-m3) → 存入 Milvus
                                        ↓
提问 → 检索最相关条文 → DeepSeek 结合条文 → 输出回答
```

两条工作流：**① PDF 入库**（写向量库） + **② 知识问答**（查向量库 + 大模型回答）。

## 五、工作流 1：劳动法规入库（B 站教程标准版）

### 链路

```
Manual Trigger → Read Files → Extract from File → Edit Fields → Milvus Vector Store
                                                            ├─ 子: Default Data Loader
                                                            └─ 子: Embeddings OpenAI (bge-m3)
```

### 每个节点精确配置

| 节点 | 关键配置 |
|---|---|
| **1. When clicking 'Execute workflow'** | 不用改（等同于 Manual Trigger） |
| **2. Read/Write Files from Disk** | Operation = **Read Files from Disk**；File(s) Selector = `D:\rag-docs\*.pdf`（通配符一次读全部） |
| **3. Extract from File** | 不用配，自动把二进制解析成 `text/pageContent`（支持 PDF / Word / Markdown 等） |
| **4. Edit Fields**（决定检索质量） | 先跑通不配置；第二步"加溯源"时加字段 `source` = 文件名（让 AI 回答时能引用"依据第 X 条"） |
| **5. Milvus Vector Store** | Connection = Milvus 自建；**Host = `127.0.0.1`**（n8n 在本机）；Port = `19530`；Operation = **Insert**；Collection Name = `labor_law`；✅ **Create Collection**（首次自动建） |
| **5a. 子节点：Embeddings OpenAI** | 选已有的 SiliconFlow 凭证；Model = `BAAI/bge-m3`（1024 维） |
| **5b. 子节点：Default Data Loader** | 默认从上游接收 pageContent；如要切块可在此设 Chunk Size |

### 验收标准

- 整条工作流跑全绿；节点 5 OUTPUT 显示插入成功 + 条数
- Attu（`localhost:3000`）刷新后 Collections 里出现 `labor_law`，点进去能看到数据（每条带 `source` 字段记原文出处）

### 与"我之前摸索版"的差异（用户参考 B 站教程后改用此版）

| 节点 | 我之前给的（旧版） | 教程版（标准） |
|---|---|---|
| PDF 解析 | 独立 Data Loader 节点 | **Extract from File**（更专业，自动识别格式） |
| 字段整理 | 无 | **Edit Fields**（关键，能加 source 元数据让 RAG 回答可溯源） |
| 切块 | 独立 Document Splitter | 教程省略（先把默认跑通，不分块也行；需要时再在 Data Loader 子节点设 Chunk Size） |

教程这套是 n8n 官方推荐的 RAG 标准模式，专业的事专业节点干。

## 六、工作流 2：知识问答 + 钉钉机器人（已完成 ✅）

**最终形态**：RAG 大脑用教程版 Q&A Chain（先在 n8n 聊天面板调试跑通），生产入口接**钉钉企业内部应用机器人**（Stream 长连接），群内 @机器人 一问一答。

### 研发链路（n8n 聊天面板调试用）

```
When chat message received
    ↓
Question and Answer Chain [LangChain]
    ├─ Model*: DeepSeek Chat Model (deepseek-chat)
    └─ Retriever*: Vector Store Retriever (Limit=4)
                    └─ Vector Store*: Milvus Vector Store (Operation = Retrieve Documents)
                                       └─ Embedding*: Embeddings OpenAI (BAAI/bge-m3)
```

### 生产链路（钉钉群 @机器人 → 回答，全链路已跑通）

```
DingTalk Node Trigger (Stream 长连接，接收 @消息)
    ↓
Question and Answer Chain  ← 同上，Model / Retriever 子节点一个字不用改
    ↓
HTTP Request  ← 🆕 关键！POST 回复到 Trigger 消息自带的 sessionWebhook
```

### 生产版节点配置清单

| # | 节点类型 | 关键配置 |
|---|---|---|
| 1 | **DingTalk Node Trigger**（社区节点 `@cryozerolabs/n8n-nodes-dingtalk`） | 凭证 = **Dingtalk API**（Corp ID / Client ID / Client Secret，不是 Robot API）；**必须选订阅事件"机器人接收消息"**（否则连上了也什么都不收）；Stream 长连接 = 机器人主动连钉钉 → **免公网 IP** |
| 2 | **Question and Answer Chain** | 不用配，自带"基于上下文回答、不知道就说不知道"的 prompt |
| 3 | （子）**DeepSeek Chat Model** | DeepSeek 凭证 → Model Name = `deepseek-chat` |
| 4 | **Vector Store Retriever** | 接 Q&A Chain 的 `Retriever*` 口；**Limit = `4`** |
| 5 | （子）**Milvus Vector Store** | Operation = **Retrieve Documents（As Vector Store for Chain/Tool）**；Collection = `labor_law` |
| 6 | （子）**Embeddings OpenAI** | SiliconFlow 凭证 → Model = `BAAI/bge-m3` |
| 7 | **HTTP Request** | Method = **POST**；URL = `{{ $('DingTalk Node Trigger').item.json.data.sessionWebhook }}`；Send Body ✅；Content Type = JSON；Specify Body = Using JSON |

**HTTP Request 的 Body（必看！直接写 JSON 模板会报 `Bad control character`，必须带 `=` 前缀整段当表达式）**：

```json
={{
  "msgtype": "text",
  "text": {
    "content": $('Question and Answer Chain').item.json.response
  }
}}
```

### 关键认知

- 触发器 OUTPUT 里的 `sessionWebhook` 是**一次性回调 URL**，POST 它 = 以机器人本人身份回复那条消息（钉钉官方群内对话模式）
- 群里 @ 的是"聊天机器人"（企业应用 bot，Stream 这个），**不是**"n8n发送消息机器人"（webhook 群机器人，只能单向群发）——俩完全不是一回事
- 回答慢（10-30 秒）是 DeepSeek 生成耗时的物理规律，正常；想快就在 System Message 加"回答 200 字以内"

### 与"我自己设计版"的差异（用户参考 B 站教程后改用此版）

| 节点 | 我之前给的（Webhook 链） | 教程版（Q&A Chain 链） |
|---|---|---|
| 触发器 | Webhook（HTTP 触发） | **When chat message received / 钉钉机器人** |
| 编排 | 手动用 OpenAI Chat Model + 自拼 prompt | **Question and Answer Chain** 一站式 Q&A（LangChain 标准） |
| 检索节点 | Milvus 直接 Get Many | **Vector Store Retriever**（中间层，解耦） |
| Milvus 模式 | Operation = Get Many | **Retrieve Documents（As Vector Store for Chain/Tool）** |
| Prompt | 自己写上下文拼接 | Q&A Chain 内置 system prompt，专业 |



## 七、踩坑记录（重点！都是真实遇到的）

### 1. `Access to the file is not allowed`（节点读不了 PDF）
**根因**：n8n 默认禁止读写任意路径，必须配置"文件系统白名单"环境变量。
**解决（一劳永逸）**：已在 Windows 设置**永久用户环境变量**，设一次管永久：

```powershell
[Environment]::SetEnvironmentVariable("N8N_RESTRICT_FILE_ACCESS_TO_CUSTOM_DIRS", "true", "User")
[Environment]::SetEnvironmentVariable("N8N_FILESYSTEM_ALLOWED_DIRECTORIES", "D:\rag-docs", "User")
```

⚠️ **设完必须重开 PowerShell / 重启 n8n 才生效**（环境变量只在进程启动时读一次）。
`start-n8n.bat` 里也写了同样的两行做双保险。以后想加白名单目录（如 `D:\others`），再执行一次第二条命令，多个目录用 `;` 分隔。

### 2. 用 `n8n start` 直启时 bat 里的环境变量不生效
bat 只在双击时读，`n8n start` 命令读不到。所以靠上面的**永久环境变量**，而不是依赖 bat。

### 3. PowerShell 里搜文本别用 bash 的 `\|`
`Select-String "A\|B"` 在 PowerShell 里是错的（`\` 不是转义符）。用：
```powershell
Get-Content 路径 | Select-String -Pattern "A","B"
```

### 4. Milvus 连接地址要分清场景
| 谁在连接 | 用什么地址 | 原因 |
|---|---|---|
| n8n（跑在本机） | `127.0.0.1:19530` | 容器端口映射到宿主机了 |
| Attu（跑在容器里） | `host.docker.internal:19530` | 容器访问宿主机要走这个特殊域名 |

### 5. 其他记住的
- Docker 拉镜像（Milvus、n8n 等）需要梯子
- C 盘紧张：Docker 镜像固定占 C 盘虚拟盘约 1GB，但数据 volumes 放 D 盘就不占 C
- n8n 一次启动会 fork 多个 node 进程（主进程 + worker），看到 4 个 node 是正常的

### 6. 钉钉机器人收不到消息（n8n 无反应）
- **触发器必须选订阅事件**（机器人接收消息）——光有 Stream 连接不订阅事件，n8n 会提示 "Waiting for you to create an event"，什么都不收
- 群里 @ 错对象：企业应用 bot（Stream）和 webhook 群机器人是两码事，触发器只听**企业应用 bot** 的 @
- 应用必须**发布**（版本管理与发布），且可见范围/白名单要包含测试人，否则客户端群列表里搜不到机器人

### 7. 钉钉回复节点选错类型（答不出/答得怪）
- ❌ "自定义机器人发送群消息"（robot.send / AccessToken）：只能**单向群发**，不能"回复到 @ 的那条消息"，且是另一个机器人账号在说话
- ✅ 正解：**HTTP Request** POST 到触发器消息自带的 `sessionWebhook`（一次性回调 URL）→ 以原 bot 身份回复
- Body 里写 `{{ }}` JSON 模板会报 `Bad control character` → 整段加 `=` 前缀当 JS 表达式求值（见"六、工作流 2"的模板）

### 8. 钉钉应用发布报 400
- 头号原因：**应用可见范围没设或没保存**；其次：机器人能力没加全、基础信息没填完（图标/描述）
- 每改一处都要单独点保存，不能攒到最后；版本号/描述别带 `& % #` 等特殊字符
